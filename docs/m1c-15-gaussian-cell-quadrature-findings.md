# M1C-15 findings — conservative Gaussian cell-volume quadrature (scoped)

Frozen pre-implementation acceptance: `docs/m1c-15-gaussian-cell-quadrature-acceptance.md` committed separately at `c1f33cda10ae611b54189e5f0df3197d7740e067`. Source solver changed minimally in `src/atmosphere/cteasAtmosphereFoam.C`; prior default `sourceShape gaussian` remains **`cellCentre`**, unchanged. Optional `sourceSpatialQuadrature cellTet4` splits each physical OpenFOAM polyhedral cell into tetrahedra from its actual volume centre, face centre and face edges; evaluates four **positive** symmetric degree-2 Gaussian quadrature points per tetra; uses real global native `mesh.V()` for normalized Bq. `writeSourceProfile true` explicitly writes the source kernel in `0/sourceProfile` for auditing only. The new option rejects unknown names and use with non-Gaussian/no-source models. This is **not exact cell Gaussian integration** and is not OpenFOAM URANS/soil/stack physics.

It still meets the separately frozen not-more-than-10%-relative-error-degradation diagnostic limit. Therefore **keep `cellCentre` default**, do not present `cellTet4` as an accuracy fix. A first-moment example also cautions against that claim: at 24³, old lumped source x-mean error -8.18e-6 m, new tetra-mode lumped x-mean error -1.915e-4 m (both not exact intra-cell integrals).
